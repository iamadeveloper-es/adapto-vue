# Chip

`adpt-chip` renders a compact, pill-shaped label. It supports five visual variants, five sizes,
optional prepend/append icons, an icon-only mode, a closable mode with a built-in remove button,
and a `clickable` toggle that switches it between an interactive control and a static badge.

- **Component name:** `AdaptoChip`
- **Source:** `src/lib/components/element/adpt-chip/index.vue`
- **Styles:** `src/lib/components/element/adpt-chip/style.scss` (injected on first render via
  `useStyle`, not registered in `AdaptoPlugin`)

## Usage

Once [`AdaptoPlugin`](../../src/lib/plugin.ts) is installed on the app, `AdaptoChip` is available
globally:

```ts
// main.ts
import { createApp } from 'vue'
import { AdaptoPlugin } from 'adapto-ui'
import App from './App.vue'

createApp(App).use(AdaptoPlugin).mount('#app')
```

```vue-html
<AdaptoChip label="Beta" color="primary-500" />
```

The chip has no slots — its visible text always comes from the required `label` prop.

## Variants

The `variant` prop controls the visual style. Default is `fussy`.

<div class="demo">
  <AdaptoChip variant="outlined" color="primary-500" label="Outlined" />
  <AdaptoChip variant="fussy" color="primary-500" label="Fussy" />
  <AdaptoChip variant="soft" color="primary-500" label="Soft" />
  <AdaptoChip variant="soul" color="primary-500" label="Soul" />
  <AdaptoChip variant="link" color="primary-500" label="Link" />
</div>

```vue-html
<AdaptoChip variant="outlined" color="primary-500" label="Outlined" />
<AdaptoChip variant="fussy" color="primary-500" label="Fussy" />
<AdaptoChip variant="soft" color="primary-500" label="Soft" />
<AdaptoChip variant="soul" color="primary-500" label="Soul" />
<AdaptoChip variant="link" color="primary-500" label="Link" />
```

| Variant    | Description                                                                            |
| ---------- | ---------------------------------------------------------------------------------------- |
| `outlined` | Transparent background with a `currentColor` border.                                    |
| `fussy`    | Border **and** a tinted (`color-mix`) background. **Default.**                          |
| `soft`     | Tinted background, no border.                                                           |
| `soul`     | Fully transparent background, no border.                                                |
| `link`     | Transparent background; hover/focus reduce opacity instead of showing the highlight.    |

Every variant is rendered with the shared `.rounded--full` utility, so the chip is always a pill.
Every variant except `link` gets a `currentColor`-based hover/focus highlight.

## Colors

The `color` prop accepts the name of a theme token (primitive, e.g. `green-500`, or semantic,
e.g. `primary-500`) as exposed on the CSS custom properties generated by the theme. It is resolved
through `fw.cv()` and applied as the chip's text color (`currentColor`), which the variants above
reuse for borders and tinted backgrounds.

<div class="demo">
  <AdaptoChip variant="fussy" color="primary-500" label="Primary" />
  <AdaptoChip variant="fussy" color="secondary-500" label="Secondary" />
  <AdaptoChip variant="fussy" color="success-600" label="Success" />
  <AdaptoChip variant="fussy" color="warning-600" label="Warning" />
  <AdaptoChip variant="fussy" color="danger-600" label="Danger" />
</div>

```vue-html
<AdaptoChip variant="fussy" color="primary-500" label="Primary" />
<AdaptoChip variant="fussy" color="secondary-500" label="Secondary" />
<AdaptoChip variant="fussy" color="success-600" label="Success" />
<AdaptoChip variant="fussy" color="warning-600" label="Warning" />
<AdaptoChip variant="fussy" color="danger-600" label="Danger" />
```

::: warning No color provided
If `color` is left empty (the default), the chip falls back to the `sm-surface-300` token instead
of the color you may expect. Always pass an explicit token to get an intentional result.
:::

## Icons

Pass `prependIcon` and/or `appendIcon` (each an `Icon` object — `{ name, size?, color?,
strokeWidth?, defaultClass? }`, forwarded to `AdaptoIcon`) to render an icon before and/or after
the label. Both can be used at once. If `size` is omitted, it is derived on mount from the chip's
computed `--adapto-chip-font-size` (plus 1px); before mount it falls back to `1rem + 1px`.

<div class="demo">
  <AdaptoChip color="primary-500" label="Download" :prepend-icon="{ name: 'download' }" />
  <AdaptoChip color="primary-500" label="Next" :append-icon="{ name: 'arrow-right' }" />
  <AdaptoChip color="primary-500" label="Range" :prepend-icon="{ name: 'calendar' }" :append-icon="{ name: 'chevron-down' }" />
</div>

```vue-html
<AdaptoChip color="primary-500" label="Download" :prepend-icon="{ name: 'download' }" />
<AdaptoChip color="primary-500" label="Next" :append-icon="{ name: 'arrow-right' }" />
<AdaptoChip
  color="primary-500"
  label="Range"
  :prepend-icon="{ name: 'calendar' }"
  :append-icon="{ name: 'chevron-down' }"
/>
```

### Icon-only chip

Combine an icon with `hideLabel` to hide the visible text. `label` is still required — it becomes
the accessible name via `aria-label`, and the icon is marked `aria-hidden`.

<div class="demo">
  <AdaptoChip variant="soul" color="primary-500" label="Filter" :prepend-icon="{ name: 'filter' }" hide-label />
</div>

```vue-html
<AdaptoChip
  variant="soul"
  color="primary-500"
  label="Filter"
  :prepend-icon="{ name: 'filter' }"
  hide-label
/>
```

## Closable chip

Setting `closable` renders a remove button (an icon-only `AdaptoButton`) next to the label and
changes the chip's DOM structure: the root becomes a `role="group"` wrapper carrying the
`aria-label`, with an inner `role="button"` span for the label/click behavior and the remove
button as a sibling — the remove button is **not** nested inside the clickable element, so
activating it never also triggers the chip's own `clicked` handler. Clicking the remove button
emits `closed` and unmounts the chip.

<div class="demo">
  <AdaptoChip color="primary-500" label="Removable tag" closable />
</div>

```vue-html
<AdaptoChip color="primary-500" label="Removable tag" closable @closed="onRemove" />
```

## Clickable chip

`clickable` (default `true`) toggles whether the chip behaves as an interactive control —
`role="button"`, `tabindex`, `aria-disabled`, and the click/keyboard (<kbd>Enter</kbd>/<kbd>Space</kbd>)
handlers that emit `clicked`. Set it to `false` to render a static, non-interactive chip (for
example, a read-only tag).

<div class="demo">
  <AdaptoChip color="primary-500" label="Static badge" :clickable="false" />
</div>

```vue-html
<AdaptoChip color="primary-500" label="Static badge" :clickable="false" />
```

`clickable="false"` only affects the label area — on a `closable` chip the remove button keeps
working regardless of `clickable`, since it is a separate control.

## States

<div class="demo">
  <AdaptoChip color="primary-500" label="Disabled" disabled />
  <AdaptoChip color="primary-500" label="Disabled closable" disabled closable />
</div>

```vue-html
<AdaptoChip color="primary-500" label="Disabled" disabled />
<AdaptoChip color="primary-500" label="Disabled closable" disabled closable />
```

- **`disabled`** — applies `is-disabled` styling (reduced opacity, `not-allowed` cursor), sets
  `tabindex="-1"` and `aria-disabled="true"` on the interactive element(s), and blocks the
  `clicked` emit. It does **not** disable the remove button's own click handling by itself — the
  remove button is a nested `AdaptoButton` that also receives `disabled`, so it is disabled too.

## Props

| Prop          | Type                                                          | Default          | Description                                                                 |
| ------------- | ---------------------------------------------------------------- | ---------------- | ----------------------------------------------------------------------------- |
| `label`       | `string` (required)                                               | —                 | Chip text. Always used as `aria-label` when `hideLabel` is `true`.          |
| `disabled`    | `boolean`                                                          | `false`           | Disables click/keyboard interaction and applies `is-disabled` styling.      |
| `color`       | `string`                                                           | `''`              | Theme token resolved via `fw.cv()`. Falls back to `sm-surface-300` when empty. |
| `variant`     | `'outlined' \| 'fussy' \| 'soft' \| 'soul' \| 'link'`               | `'fussy'`         | Visual style of the chip.                                                    |
| `size`        | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'`                              | `'xs'`            | Controls padding and font size.                                              |
| `prependIcon` | `Icon` (`{ name, size?, color?, strokeWidth?, defaultClass? }`)    | `undefined`       | Icon rendered before the label.                                              |
| `appendIcon`  | `Icon` (`{ name, size?, color?, strokeWidth?, defaultClass? }`)    | `undefined`       | Icon rendered after the label.                                               |
| `hideLabel`   | `boolean`                                                          | `false`           | Hides the visible label; the label is still exposed via `aria-label`.       |
| `closable`    | `boolean`                                                          | `false`           | Renders a remove button and switches to the group-wrapper DOM structure.    |
| `clickable`   | `boolean`                                                          | `true`            | Enables click/keyboard interaction and `role="button"` on the label area.   |

::: tip
`size`'s type is the shared `Size` alias (`'xs' | 'sm' | 'md' | 'lg' | 'xl'`), but the prop itself
is declared as a plain `String` at runtime — TypeScript enforces the literal values at the call
site, not the component.
:::

## Emits

| Event    | Payload                       | Description                                                                 |
| -------- | -------------------------------- | ------------------------------------------------------------------------------ |
| `clicked` | `MouseEvent \| KeyboardEvent`   | Emitted on click or Enter/Space, unless `disabled` or `clickable` is `false`. |
| `closed`  | `MouseEvent`                    | Emitted when the remove button (`closable`) is activated (the remove button is a native `<button>` via `AdaptoButton`, so this also fires on Enter/Space). |

## Slots

`adpt-chip` has no slots. The label is only settable through the `label` prop.

## Accessibility

- **Non-closable chip** — the root `<span>` gets `role="button"` when `clickable` is `true`,
  `tabindex="0"` (or `-1` when `disabled`), and `aria-disabled` mirroring the `disabled` prop.
  When `clickable` is `false`, none of these attributes are rendered and the chip is not part of
  the tab order.
- **Closable chip** — the root `<span>` becomes `role="group"` with `aria-label="label"` (always
  present, regardless of `hideLabel`); the inner content `<span>` repeats the same
  `role`/`tabindex`/`aria-disabled` pattern as the non-closable chip, kept separate from the
  remove button so the two controls never compete for the same click.
- `hideLabel` sets `aria-label="label"` on the interactive element so assistive technology still
  announces the text even though it isn't visually rendered.
- Prepend/append icons are always marked `aria-hidden="true"`.
- When a focused chip is closed, focus moves to the chip's next sibling element in the DOM (if
  one exists), so keyboard users aren't dropped back to the document body.
